# Jump

## Usage

`<ref>` is a feat's or a dive's quid. A feat is any doc one of the hero's roots reaches through links whose rel ends `.feat`, a root of kind cape aside, since its feats are actions, a memo unless it has a kind of its own; a doc nothing reaches that way is refused, naming how to link it in. Its `scopes` name the repos it works in, legacy's shape: an entry keyed by a repo doc's quid, with `work-branch` naming the branch its work goes to, and an entry with none, or a bare quid, read-only. A dive's read-only scope is written as an entry with none (`<repo>: {}`), which core reads a bare quid as.

Without `<ref>`, jump takes the dive this worktree holds; else the one open dive nobody holds that the pilot packed or nobody has touched; with none or several, it refuses, naming each.

- **A feat**: mints a dive on it (see [dive](01a15bb2-5092-7858-90dd-e6c5b1b45254.md)), copying its scopes, naming the feat in its `meta.feat`, and linking it from the feat as `dives.feat`; then jumps it.
- **A dive**: refused when it is over, when another holder has it, or when this worktree holds another dive. Any dive nobody holds may be jumped by name, whoever packed it.

Jumping the dive this worktree holds again records nothing: each scope whose checkout is missing or elsewhere is put where the dive wants it, and a checkout already there is left as it is.

Otherwise, everything is checked before anything moves, then done locally, and only then pushed:

1. Refused while the hero has uncommitted changes, holds commits origin's trunk lacks, or a checkout to be moved has uncommitted changes or untracked files, naming each. A hero behind trunk is fast-forwarded.
2. The hero's bookkeeping commit is made on origin's trunk: the dive minted when jumping a feat, `diver` set to this holder, `packer` cleared, each scope's `ref` set to the dive's newest ref on its origin, and a `## <timestamp> jumped` section.
3. The dive's newest ref on the hero's origin is replayed on top of it. A conflict aborts the replay and resets the hero to trunk.
4. Each writable scope's checkout is put on the dive's local branch, hydrated for the dive with core's hydrate-repo when missing, moved when there for other work, its commits origin lacks pushed to an orphan ref first. Where the dive's newest ref holds what the branch lacks, the branch moves to it; when the work branch on origin has moved on, the work is rebased onto it. A conflict aborts the rebase and resets the hero to trunk. Each read-only scope's checkout is detached at origin's trunk.
5. The bookkeeping commit alone is pushed to the hero's trunk. When trunk moved meanwhile, jump fetches it, refuses if someone else now holds the dive, and otherwise makes steps 2 and 3 again on the new tip.

Then each checkout moved from other work has its ignored files swapped for the feat's pack (see dive), and pack's `work in progress` commit is undone in the hero and each scope, so the work it held comes back uncommitted. It prints the dive's path, its feat's and each checkout's.

## Canonical dives

A feat's dive is minted as `work:dive` (see [dive](01a15bb2-5092-7858-90dd-e6c5b1b45254.md)), found with find-kind and pinned with core's pin-of, so the dive carries work's canonical scope; a schema that is not published refuses the jump before any checkout moves. Dives and feats are recognised by doc-kind, never by the text of `kind`.
