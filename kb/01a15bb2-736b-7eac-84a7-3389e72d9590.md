# Jump

`<ref>` is a feat's or a dive's quid.

- **A feat**: mints a dive on it (see [dive](01a15bb2-5092-7858-90dd-e6c5b1b45254.md)), pinning each scope at its work branch's tip, else trunk's, so a feat's dives stack; then jumps it.
- **A dive**: refused when it is over, when someone else holds it, or when another dive is on deck. Jumping the dive already on deck jumps it again.

For each scope, jump checks the repo out with core's hydrate-repo, fetches it, and moves the checkout:

- With work on the dive's ref, to that work. When the work branch has moved past the pin, the work is rebased onto the branch first and the pin moves with it. A rebase that conflicts is left in progress, named, for the pilot to finish with `git rebase --continue`, and jump exits 1 before recording anything.
- With none, to the pin.

A checkout with uncommitted changes, or on commits that neither the pin nor the dive's ref holds, is refused before anything moves, naming each: moving it would lose work no ref holds.

The work pack left uncommitted comes back uncommitted: pack's `work in progress` commit is undone.

It sets `diver`, clears `packer`, appends `## Jumped`, puts the dive on deck, and prints the dive's path, its feat's and each checkout's.
