# Dive on deck

Finds the dive on deck from the hero's branch (dive-branches), among the open dives: the docs of work's dive kind that core's feat-tree reaches, as a feat links them `dives.feat`, with no `meta.outcome`, which work, not core, picks out by kind: a branch `nosedive-<token>-<dive id>` whose dive id names an open dive in the hero, and whose `diver` carries that token (see [dive](01a15bb2-5092-7858-90dd-e6c5b1b45254.md)); and its home, the local branch whose holder token is that token (loop-returns-home). It returns them with the feat the dive's `meta.feat` names and its scopes. Given a dive's quid, it refuses unless that is the one. Off a dive branch it refuses, naming `jump`; a dive branch whose dive is over or held by another token, as a copied branch's would be, is refused, as is a home that is gone: recreate it.

Each scope carries its repo doc, its checkout, the repo's trunk, the work branch, if any, and whether its checkout is the dive's: on the dive branch when writable, present when read-only. Nothing is hydrated or moved.

## Kind identity and scopes

Docs are told apart by core's doc-kind, not by the text of `kind`: a dive is a doc whose owner is work and whose name is `dive`, a repo doc is core's by its place in `.nosedive/repos`, and a cape root is skipped when walking feats. The kind of a feat is found with find-kind, spelled in the hero's terms, to learn whether it is durable.

Only an entry keyed by a repo doc the hero registers is a work scope. Every other entry is not work's to read: the one with `canonical: true` naming the owner of the doc's kind, and any meta entry keyed by a seeded id carrying `version`, `schema` or `meta`. None is checked out, and when a dive's refs are rewritten each is kept exactly as parsed.

## Turns and records

The module also holds what turn, jump, land, pack and bail share for turns (turns-publish-when, turns-pushed-where). `turnCommits` lists the turn commits in a range: nosedive's own, not a merge, not a work-in-progress commit, each changing only the dive doc. `recordBase` gives the dive doc a put-down's record is built on, the dive branch's copy, which holds every turn, and counts the turns the dive made since its base. It is where the moved-home guard sits: the home's copy of the dive doc at its tip, compared with its copy at the dive's base, is fine unchanged, or when the dive's copy begins with it, as a dive in flight with turns already on main has; otherwise it refuses, before anything is changed, with `<doc> on <home> changed since this dive began, by <sha> <subject>, so nothing was put down (landed, for land) and every turn is still on <dive branch>: revert that change on <home>, or ask whoever made it to, then run \`nosedive <command>\` again`. When an earlier run of the put-down already published part of the work, which the home moving after the work and the dive refs were pushed leaves, it instead says the command is only partly done, names what was published and what was not and the command to run again, and still touches nothing (put-down-home-race); `assertHomeUnmoved` judges the home on a fresh fetch just before the first push, so only a move inside that window gets the partial message. The push of the record, fast-forward only and leased on the home's tip, is what stops an overwrite; the refusal names the cause and never throws a turn away. The record commit itself is the record-dive function's, given the dive branch's copy as its base. Nothing here puts a turn on the home.

The dive's ref in each repo is `diveRef`, and the sha this dive last left on it is kept in the checkout as the local ref `leaseRef`, read by `leased`: never pushed or fetched, set by jump from the ref it observed, moved by a turn, pack or land only once its push has succeeded (turn-lease-sha-kept-where). `backUp` is the turn's push: each writable scope's committed tip, then the hero's, to the dive's ref under `--force-with-lease=<ref>:<sha>` on that sha, never bare (turn-push-lease), through core's commit-plan. It commits nothing and names the repos holding uncommitted changes, and a push that is refused or offline is reported and leaves the work committed.
