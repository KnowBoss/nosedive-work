# Dive on deck

Finds the dive this worktree holds, among the open dives core's feat-tree finds by walking the feats the hero's roots reach, the one definition work and commit-subject share, whose `diver` carries its holder token, which core's commit-subject computes and reads to name the held dive's feat in commits (see [dive](01a15bb2-5092-7858-90dd-e6c5b1b45254.md)), and returns it with the feat its `meta.feat` names and its scopes. Given a dive's quid, it returns that one, refusing it unless this worktree holds it. With none it refuses, naming `jump`; with several, it refuses naming each, with the repos on its branch and the commits each holds origin lacks, so the pilot can name one.

Each scope carries its repo doc, its checkout, the repo's trunk, the work branch, if any, and whether its checkout is the dive's: on the dive's local branch when writable, present when read-only. Nothing is hydrated or moved.

## Kind identity and scopes

Docs are told apart by core's doc-kind, not by the text of `kind`: a dive is a doc whose owner is work and whose name is `dive`, a repo doc is core's by its place in `.nosedive/repos`, and a cape root is skipped when walking feats. The kind of a feat is found with find-kind, spelled in the hero's terms, to learn whether it is durable.

Only an entry keyed by a repo doc the hero registers is a work scope. Every other entry is not work's to read: the one with `canonical: true` naming the owner of the doc's kind, and any meta entry keyed by a seeded id carrying `version`, `schema` or `meta`. None is checked out, and when a dive's refs are rewritten each is kept exactly as parsed.
