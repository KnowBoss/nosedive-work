# Dive on deck

Finds the dive on deck from the hero's branch (dive-branches): a branch `nosedive/<token>/<dive id>` whose dive id names an open dive in the hero, and whose `diver` carries that token (see [dive](01a15bb2-5092-7858-90dd-e6c5b1b45254.md)); and its home, the local branch whose holder token is that token (loop-returns-home). It returns them with the feat the dive's `meta.feat` names and its scopes. Given a dive's quid, it refuses unless that is the one. Off a dive branch it refuses, naming `jump`; a dive branch whose dive is over or held by another token, as a copied branch's would be, is refused, as is a home that is gone: recreate it.

Each scope carries its repo doc, its checkout, the repo's trunk, the work branch, if any, and whether its checkout is the dive's: on the dive branch when writable, present when read-only. Nothing is hydrated or moved.

## Kind identity and scopes

Docs are told apart by core's doc-kind, not by the text of `kind`: a dive is a doc whose owner is work and whose name is `dive`, a repo doc is core's by its place in `.nosedive/repos`, and a cape root is skipped when walking feats. The kind of a feat is found with find-kind, spelled in the hero's terms, to learn whether it is durable.

Only an entry keyed by a repo doc the hero registers is a work scope. Every other entry is not work's to read: the one with `canonical: true` naming the owner of the doc's kind, and any meta entry keyed by a seeded id carrying `version`, `schema` or `meta`. None is checked out, and when a dive's refs are rewritten each is kept exactly as parsed.
