# Dive branch dashes

Work named a dive's branch `nosedive/<token>/<dive id>` until git refused it in a hero with a branch named `nosedive`: a ref cannot be both a branch and a folder of branches. It is `nosedive-<token>-<dive id>` now, one segment (see dive, dive-branch-dashes), and a dive branch of the old shape is no longer read as one.

This migration renames this checkout's old-shaped dive branches, in the hero and in each git checkout in its workspace, with `git branch -m`, so a branch checked out keeps its place and its upstream. Only branches whose token is one of the hero's own branches' are renamed: a scope's cache is shared with any other hero checking the repo out, and that hero's dives are its own to rename when it is seeded. It renames nothing the second time, and says how many it renamed.
