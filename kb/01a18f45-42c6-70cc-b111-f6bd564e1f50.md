# Turn

## Usage

`pass --turn <dive> [<summary>] [--next <gist>] [--label <label>]` records progress on the dive on deck, the one the hero's dive branch names, as found by dive-on-deck. A different dive is refused. `-` as summary reads stdin.

Append a section headed `## <ISO 8601 timestamp>[ <label>]`, then the summary when given, then `Next: <gist>` when given. Use core's hero-zone timestamp helper once available; until then use UTC with `Z`. Refuse when neither summary nor next is given, or next contains more than one line. Two turns append in order. Edit through pass so each turn makes one ordinary pass commit. The gate sets no commit subject; core's pass owns it.

Turns live on the dive branch and its dive ref, and reach the home only when land, pack or bail puts the dive down. Each turn is committed on the dive branch and pushed, never to the home, to the dive's ref, `refs/nosedive/<token>/<work id>/dive.<dive id>`, in the hero and in each writable scope's repo, the token being the diver token of the checkout that holds the dive. Uncommitted changes are not backed up: a turn commits none and pushes only what is committed, and it warns, naming each repo that holds some. A push that is refused or offline keeps the turn committed and warns; the next turn, pack or land pushes it. A scope that is not pushed keeps the hero from being pushed, so the hero's ref never describes code its scopes' refs lack.

## Where a turn lives

A turn is committed on the dive branch and pushed to the dive's ref, never to the home (turns-publish-when, turns-pushed-where). It stays a pass gate (turn-stays-a-pass-gate), so each turn is one ordinary pass commit on the dive branch; the dive's home, the branch it was jumped from, and its upstream are not touched, so main shows no noise while the dive is worked.

Once pass has committed, the gate pushes the committed tip of each writable scope's checkout on the dive branch that holds commits its base lacks, then the hero's, to `refs/nosedive/<token>/<work id>/dive.<dive id>` in that repo's origin: the ref pack keeps and jump picks the dive up from (turn-pushes-scopes). It makes no work-in-progress commit, so each repo holding uncommitted changes is named in a warning: they are not backed up. It then prints, and exits 0:

`turn: <sha> committed on the dive branch and pushed to its dive ref in <repos>; the home gets it only when land, pack or bail puts the dive down`

A push that is refused or offline keeps the turn committed, warns naming the repo and says so, and the line says `not pushed`; the next turn, pack or land pushes it. A core that gives gates no `ctx.committed` cannot push after pass has committed: the gate says so, and pack or land pushes the turn.

Every ref nosedive writes to a repo's origin is `refs/nosedive/<owner>/<cape id>/<slug>` (nosedive-ref-scheme): the owner is a diver token as tokenOf makes it, a hash of the checkout's path, its home branch and the email, or `hero`; the cape is work; the slug is dotted, with no slash. A dive's work is `dive.<dive id>` under the token of the checkout that holds the dive, which alone pushes it, with a plain force: a rebase needs no lease, and a second holder's checkout, a takeover or a crashed agent coming back, has another token and pushes another ref, so nothing of either is overwritten. Jump, pack and land read the ref of the token that holds the dive, which is the one the dive doc records once it is packed, never another token's newer one, and a land or a bail deletes the dive's refs under every token. The name from before this, `refs/nosedive/<hero id>/dives/<dive id>`, is still read, so a dive packed under it jumps and lands, and a put-down deletes it. No nosedive ref is local only: markers are refs on origin, and commits moved off a branch go to a bundle (see jump).

The push names the sha that `git ls-remote` has just read for the ref, so it is in effect a lease against this checkout's own ref: a race between two processes in one checkout refuses instead of clobbering. That is a deliberate tightening of the plain force. A scope that holds nothing beyond its base, as when its holder reset it, but whose own dive ref exists has that ref deleted, and a deletion that fails keeps the hero from being pushed as a failed push does. Turn commits are told by the subject `feat(<dive name>): pass turn` and a change to the dive doc only, which held-dive-doc-edits keeps to turns, not by their committer, which a rebase changes.

The next land, pack or bail publishes the turns to the home: each builds its record on the dive branch's copy of the dive doc, which holds every turn section, so the one record commit it pushes carries them all, and the record's lines say `- turns: <n>`. Land and jump leave the turn commits themselves out of the hero work they replay, so a section is never doubled (see land and jump), and pack and land do not double the turns already on the dive ref: pack leaves the ref at the dive branch's tip, which is where the last turn left it. A record refuses, changing nothing, when the home's copy of the dive doc changed since the dive began: every turn stays on the dive branch (see dive-on-deck).

A worktree lost before then loses the dive branch's uncommitted changes, which no turn backs up; its committed work and turns are on the dive ref.

The dive doc is changed only by turns and records while the dive is held: crud refuses to edit it (held-dive-doc-edits, see dive-shape). A dive in flight whose turns already reached main under turns-on-jumped-branch still lands: its record is built on the dive branch's copy when that begins with the home's.
