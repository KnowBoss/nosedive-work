# One attempt on a feat, by one diver at a time, its work kept in its repos until it lands

A dive is one attempt on a feat. It is not durable: once it is over, it can go.

`jump` mints it on its feat, named `<feat name>.<last 6 of its id>`, in the ship's kb. It links its feat as `parent.feat`, and the feat links it as `child.feat`, so the tree shows the dives under their feat.

Its `scopes` copy the feat's, each adding `pin`: the commit its work starts from, the tip of the scope's work branch when there is one, else of trunk.

- `meta.diver` is who holds it, by git's `user.email`, and null when nobody does.
- `meta.packer` is who last put it down.
- `meta.outcome` is `landed` or `bailed` once it is over, and absent while it is open.

Each action that changes a dive appends a section to it, `## <Action> <iso time>`, saying what it did, scope by scope.

## On deck

A ship has at most one dive on deck: the one this checkout of the ship is working, named by id in `.nosedive/local/dive`, which git ignores. jump puts it there; pack, bail and land take it off.

## Work stays in git

A dive's work is never copied into the ship. Until it lands, each repo's work lives on `refs/nosedive/dives/<dive id>` on that repo's remote: a ref outside `refs/heads`, so no branch listing shows it and no clone fetches it, yet any ship that knows the dive can fetch it by name.
